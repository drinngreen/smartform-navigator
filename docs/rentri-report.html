Analisi e richieste all’esperto RENTRI

  • Issuer ↔ Operatore REST ↔ Registro REST: gli ID in path devono appartenere all’operatore del certificato (dal dnQualifier), altrimenti 401.
  • Chiediamo: ID REST dell’operatore per Global/MULTY e ID registro REST corretti, e conferma del flusso per “Trasporto Conto Proprio”.
  • Conferma formato iss: preferire dnQualifier; precisare se sono ammesse varianti (CF:IT-..., numerico).
  • 403 su MULTY: chiarire ACL/ruoli/permessi richiesti per “movimenti” di quel registro.

Piano di sblocco

  1. Recupero ID REST operatore/registro corretti per ciascun certificato.
  2. Aggiornamento URL → operatore/<ID_OPERATORE_REST>/movimenti o “registrazioni” coerente.
  3. Firma JWT con iss = dnQualifier dell’operatore del path; headers e digest già conformi.
  4. Invio singolo: attesa 202 e transazione_id via /check-status; conferma su /list-registrazioni.
  5. Lockstep massivo dopo esito positivo.
